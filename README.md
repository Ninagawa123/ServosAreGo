# ServosAreGo

ESP32 と半二重通信回路を使って、**各社のシリアルサーボと PWM サーボ**を
シリアルモニターから対話的に設定・確認・動作テストするためのツールです。

- 1 つのファームウェアで 8 種類のサーボを扱えます。起動時のメニューで種類を選びます。
- `[0]` で、つながっているサーボの種類と通信速度を**自動で判別**します。
- キーの働きは全種類で共通です（例：`f` 検索、`x` 角度、`i` ID 変更、`t` 送信テスト）。
- 送信と受信の回路（3 ステートバッファ版 / SN74LXC1T45 版）を自動で判定します。

これまでの 6 つの Servo Setter（Feetech / Dynamixel / Futaba / JR XBUS / Hitec / Kondo）を 1 つにまとめ、
PWM サーボを加えたものです。

## 必要なもの

| 項目 | 内容 |
|---|---|
| マイコン | ESP32（PlatformIO の `esp32dev`）。Meridian Board を想定 |
| 回路 | 半二重通信回路（3 ステートバッファ版、または SN74LXC1T45 版。どちらも自動判定） |
| サーボ | 上の表のサーボ（TTL レベルの 1 線式。RS-485 版は対象外） |
| 電源 | サーボの定格電圧に合った電源 |
| 開発環境 | [PlatformIO](https://platformio.org/)（VSCode 拡張または CLI） |

## 配線と回路

すべての種類で同じピンを使います。

| 信号 | ESP32 ピン | 設定場所 |
|---|---|---|
| TX | GPIO 27 | `platformio.ini` の `-D TX1=27` |
| RX | GPIO 32 | `platformio.ini` の `-D RX1=32` |
| EN / DIR（送受信切替） | GPIO 33 | 各 `src/setter_*.cpp` の `PIN_EN` |
| GND | GND | サーボ電源と ESP32 の GND を共通にする |

- Meridian Board の **L 系統**（Serial1）と同じピンです。
- PC とのシリアルモニター速度は **115200 bps** です。
- サーボとの通信速度と形式（8N1 / 8E1 / 8N2、信号の反転）は、選んだ種類に合わせて自動で設定されます。

### 回路の自動判定（エコー）

各種類のツールが始まるときに、サーボに無視されるダミーバイト `0x55` を 3 回送り、
自分の送信が受信側に返ってくるか（エコー）を調べます。

| 判定結果 | 回路 | 動作 |
|---|---|---|
| エコーあり | SN74LXC1T45 版（TX と RX が同じ端子に直結） | 受信したエコーを照合して読み捨てる。**受信中は TX の出力を切る**（信号のぶつかりを防ぐ） |
| エコーなし | 3 ステートバッファ版 | そのまま応答を読む |

結果は起動時のログに `Servo bus echo: ...` と出ます。

## ビルドと書き込み

`ServosAreGo/ServosAreGo/` フォルダ（`platformio.ini` がある場所）で実行します。

```bash
pio run              # ビルド
pio run -t upload    # ESP32 に書き込み
pio device monitor   # シリアルモニターを開く（115200 bps）
```

> シリアルモニターは **改行コードを送る設定**（LF / CR / CRLF のいずれか）にしてください。

## はじめの使い方

1. **書き込んでシリアルモニターを開く**と、サーボ種類のメニューが出ます。
2. **種類がわかっていれば番号**、わからなければ **`0`（自動判別）** を入力してリターンします。
3. 種類ごとのメニューが出たら、**`f` でサーボを探します**（ターゲット ID と一斉制御リストが自動で設定されます）。
4. **`t` で動くか確かめます**（返信が読めなくても動きます）。
5. 必要に応じて **`i` で ID を変更**、**`b` で通信速度を変更**します（ID の変更は 1 台ずつつないで行います）。
6. 別の種類のサーボを使うときは、**`h` で種類を選び直します**。

## サーボ種類の選択

起動すると、サーボ種類のメニューが出ます。番号を入力してリターンします。

```
============================================
ServosAreGo - Select servo type:
  [0] Detect servo type
  [1] PWM servo (50 Hz, no reply)
  [2] Feetech STS (STS/SMS series)
  [3] Feetech SCS (SCS series)
  [4] Dynamixel (Protocol 2.0)
  [5] Futaba TTL (RS30x)
  [6] JR XBUS
  [7] Hitec HSR (HMI)
  [8] Kondo KRS (ICS3.5/3.6)  <- current
Enter number (Enter: keep current, auto start in 5 s):
```

- 選んだ種類は ESP32 の NVS（不揮発メモリ）に保存されます。
- 次回からは、**リターンだけ、または 5 秒間入力がなければ、前回の種類で起動**します。
- 初めて起動したときは、番号を選ぶまで待ちます。
- 動作中に **`h`** を入力すると、種類を選び直せます。
  - 違う種類を選ぶと、保存して ESP32 を再起動します。再起動後はメニューを出さずに、その種類ですぐ始まります。
  - 同じ種類を選ぶか、リターンだけなら、元のメニューに戻ります。
  - `0` を選ぶと、再起動してから自動判別します（動作中の種類がバスを使っているため）。

## 自動判別

`0` を入力すると、**読み取りのコマンドだけ**を送って、応答したサーボの種類と通信速度を調べます。
位置の指令は送らないので、サーボは動きません。

```
Detecting servo type (read commands only, servos do not move)...
Scan range: ID0-31 (Kondo), ID0-20 (Feetech/Dynamixel), ID1-20 (Futaba/XBUS)
  Kondo KRS        115200 bps ... -
  Kondo KRS        other baud rates ... -
  Feetech STS/SCS  1000000 bps ... -
  Dynamixel        57600 bps ... found
Detected: Dynamixel (Protocol 2.0) at 57600 bps
Servo type: Dynamixel (Protocol 2.0)
```

- 見つかった種類で、**見つかった通信速度のまま**ツールが始まります。種類は保存されます（通信速度は保存しません）。
- 最初に見つかった種類で止まります。続けて `f` を使うと、その種類のサーボを全部探せます。
- 全部調べると 10 秒ほどかかります。

### 調べる順番

| 順番 | 種類 | 通信速度 | 調べる ID | 使うコマンド |
|:-:|---|---|---|---|
| 1 | Kondo KRS | 115200 → 1250000 / 625000 | 0〜31 | パラメータ読み出し（スピード） |
| 2 | Feetech STS / SCS | 1 Mbps | 0〜20 | レジスタ読み出し（アドレス 2 = END。0 = STS、1 = SCS で系列も判別） |
| 3 | Dynamixel | 57600 | 0〜20 | PING |
| 4 | Futaba TTL | 115200 | 1〜20 | メモリ読み出し（型番） |
| 5 | JR XBUS | 250000 | 1〜20 | GET（型番） |
| 6 | Hitec HSR | 19200 | なし（1 台だけ） | バージョンと ID の読み出し（0xE7）を最大 4 回 |
| 7 | Feetech / Dynamixel / Futaba | 上以外の全速度 | 同上 | 同上 |
| 8 | PWM サーボ | — | — | **確認してから** ±30° で往復させ、動いたかを目で確かめる |

- 近藤の ICS は位置の指令にチェックサムがないため、他のプロトコルの送信を誤って受け取らないよう、最初に調べます。
- 各種類の工場出荷時の速度を先に調べ、そのあとで他の速度を調べます。
- **ID が範囲外のサーボは見つかりません**。そのときは手動で種類を選び、`f` で範囲を広げて探してください。
- **Hitec**：ID なしで読み出すため、**1 台だけ**つないでください。
  サーボがいなくても線の状態が値として読めてしまうため、0x00 / 0xFF 以外の同じ値が 2 回続けて返ったときだけ「見つかった」とします。
  Hitec の信号の極性に切り替えてから 1 秒待って読みます。見つからなかったときは、最後に読めた値を
  `(last 0xE7 reply: ...)` と表示します。
- **JR XBUS**：返信が読めることが前提です。送信はできても返信が読めない回路では見つかりません。

### PWM サーボの確認

シリアルサーボが見つからなかったときだけ、PWM サーボを試すか聞きます。

```
No serial servo detected. (Hitec reads need only ONE servo on the bus.)
Try PWM servo? A 50 Hz PWM sweep is sent on the signal line.
(Some serial servos, e.g. XBUS, stay in PWM mode until power-cycled.)
[y] Try / Enter: skip
y
Sweeping +/-30 deg by PWM...
If the servo moves, press Enter. Otherwise type n + Enter (auto stop in 10 s).
```

- PWM サーボは返信しないため、**動いたかどうかを目で確かめる**方式です。動いたらリターンで PWM サーボに決まります。
- XBUS サーボなどは、電源投入後に PWM を先に受けると、電源を入れ直すまで PWM モードのままになります。
  そのため、PWM は聞いてから出します。
- 何も見つからなければ、種類のメニューに戻ります（手動で選んでください）。

## コマンド一覧

コマンドは 1 文字を入力してリターンします。空のままリターンするとメニューを表示します。
**同じキーは、どの種類でも同じ働き**です。

| `f` | サーボを探す | ○ | ○ | ○ | ○ | ○ | ○ | — |
| `z` | ターゲット ID の設定 | ○ | ○ | ○ | ○ | ○ | ○ | — |
| `n` | 一斉制御 ID リストの設定 | ○ | ○ | ○ | ○ | ○ | ○ | — |
| `v` | 電圧などの読み取り ※1 | ○ | ○ | ○ | ○ | ○ | ○ | — |
| `r` | 現在位置の読み取り | ○ | ○ | ○ | ○ | ○ | ○ | — |
| `a` | 全サーボの位置の読み取り | ○ | ○ | ○ | ○ | — | ○ | — |
| `c` | 全サーボを中央へ | ○ | ○ | ○ | ○ | ○ | ○ | ○ |

| `p` | レジスタなどの読み取り ※2 | ○ | ○ | ○ | ○ | ○ | ○ | — |

| 種類 | キー | 働き |
|---|---|---|
| Futaba | `l` | 返信の遅れ時間の設定 |
| XBUS | `w` | 動かして ID を探す（送信のみ） |
| Hitec | `k` | 速度の設定 |
| Hitec | `y` | Go / Stop（0xEB） |
| Hitec | `j` | 制御パラメータセットの選択（0xEA） |

| Kondo | `l` | EEPROM の全設定の表示 |

| PWM | `w` | パルス幅（µs）を直接指定 |

## 送信テスト（t）

ESP32 からサーボへの送信（TX）だけで、サーボが動くかを確かめます。**返信が読めなくても動きます**。
全 ID に +30° → -30° → +30° → -30° → 中央 の順に、0.7 秒ごとに位置指令を送ります。

| 種類 | 送り方 | 終わったあと |
|---|---|---|
| PWM | 信号線にパルス | 中央でパルスを出したまま。`d` で止める |
| Feetech / Dynamixel / Futaba | ブロードキャスト（全 ID）でトルク ON と位置指令 | トルク ON のまま中央。`d` で脱力 |
| JR XBUS | ID1〜50 にチャンネルデータを 5 秒間送る | 脱力 |
| Hitec | ID0〜127 に位置指令 | 中央で保持 |
| Kondo | ID0〜31 に位置指令（返信した ID を表示） | 中央で保持 |

- 今の通信速度で送ります。動かないときは、`b` / `f` で通信速度を確かめてください。
- Dynamixel は位置制御モード（工場出荷時の設定）のサーボだけが動きます。
- **動くのに `f` で見つからない**ときは、送信は正常で、受信（RX）側か通信速度に問題があります。

## PWM サーボ

信号線（TX）に 50 Hz の PWM を出します。返信がないので、ID・通信速度・読み取りはありません。

| キー | 働き |
|---|---|
| `x` | 角度を指定して動かす（-100°〜+100°） |
| `c` | 中央（1500 µs） |
| `t` | 送信テスト（+30° → -30° → +30° → -30° → 中央） |
| `e` | パルスを出す（最後のパルス幅で保持） |
| `d` | パルスを止める（多くのサーボは脱力します） |
| `w` | パルス幅（500〜2500 µs）を直接指定 |
| `h` | サーボ種類の選び直し |

- 角度は **1500 µs が中央、10 µs / 度**で計算します。サーボによって角度の比率は違います。
- 起動時はパルスを出しません（サーボは動きません）。
- 半二重回路の EN を送信方向に固定し、TX ピン（GPIO 27）から LEDC でパルスを出します。
- **シリアルモードのサーボは PWM では動きません**。
  近藤の ICS サーボは、電源を入れたときに信号線が LOW だと PWM モード、500 ms 以上 HIGH だとシリアルモードになります。

## 注意点

- **Feetech（`[2]` / `[3]`）を選ぶと、起動時に ID1〜6 を中央位置へ動かします**（統合前のツールと同じ動作）。
  サーボが急に動くことがあるので注意してください。
- **ID・通信速度・EEPROM の書き換え**（`i` `b` `s` `k` `o` `q` など）はサーボに保存されます。
  ID を変えるときは、**変えたいサーボを 1 台だけ**つないでください。
- **Hitec の読み出しと ID 変更**は ID なしで行うため、**1 台だけ**つないでください。
- **Kondo の ID コマンド**は、実行後 500 ms ほどサーボが応答しません（ツールは 520 ms 待ちます）。
- 通信速度を変えたあとは、ESP32 側も同じ速度に合わせる必要があります（`b` の手順に従ってください）。

## トラブルシューティング

| 症状 | 考えられる原因 | 対処 |
|---|---|---|
| 自動判別で何も見つからない | 配線・電源、ID が調べる範囲の外、返信が読めない | 配線と電源を確かめる。手動で種類を選んで `t` で動くか確かめ、`f` で範囲を広げて探す |
| `t` で動かない | 電源・配線・通信速度・モード | 電源と信号線を確かめる。`b` / `f` で通信速度を合わせる。電源を入れ直す |
| `t` で動くが `f` で見つからない | 受信（RX）側の問題、通信速度の違い | `g`（受信ダンプ）で受信を確かめる。`f` の全速度検索を使う |
| Hitec が見つからない | 2 台以上つないでいる、信号の極性 | 1 台だけつなぐ。`u` で極性を切り替える。`[7]` を選んで `f` を試す |
| XBUS が見つからない | 返信が読めていない | `t` / `w` で送信だけで確かめる（詳しくは [docs](docs/JR_XBUS_Servo_Setter.md)） |
| 書き込み直後、前回の種類で起動しない | 保存の形式が変わった（番号の並びを変更） | 一度だけ番号を選び直す |
| 違う種類で起動してしまう | 前回の種類が保存されている | 起動時に 5 秒以内に番号を入れるか、動作中に `h` で選び直す |

種類ごとの症状と対処は、`docs/` の各ファイルの「トラブルシューティング」を見てください。

## 統合前のツールとの違い

共通のキーの働きを揃えるため、次の点を変えました。それ以外の操作は統合前と同じです。

| 種類 | 統合前 | ServosAreGo | 理由 |
|---|---|---|---|
| Feetech | `t` STS / SCS の切り替え | なし（起動時のメニューで `[2]` STS / `[3]` SCS を選ぶ） | `t` は送信テストに揃えた |
| Feetech | 起動時に ID1〜6 から系列を自動判定 | メニューで選んだ系列で始める | 選んだ種類を優先するため。`f` での自動判定は従来どおり |
| Hitec | `o` Go / Stop | `y` | `o` は回転方向の設定に揃えた |
| Kondo | `m` EEPROM の表示 | `l` | `m` はバージョンの読み取りに揃えた |
| Feetech / Dynamixel / Futaba | — | `t` 送信テスト | 全種類で使えるようにした |
| すべて | — | `h` サーボ種類の選び直し | 追加 |
| — | — | PWM サーボ、自動判別 `[0]` | 追加 |

統合前の 6 つのツールのフォルダは、そのまま残してあります。

## 技術メモ

- 各 `setter_*.cpp`（PWM 以外）は、統合前の各ツールの `main.cpp` を、ほぼそのまま `namespace`
  （`feetech` / `dynamixel` / `futaba` / `jrxbus` / `hitec` / `kondo`）で包んだものです。
  変更したのは、上のキーの違い、`h` と `t` の追加、自動判別用の `detect()` / `presetBaud()` の追加です。
- 種類ごとに UART の設定やタスク（XBUS のチャンネルデータ送信など）が違うため、
  種類を選び直したときは状態を残さないよう ESP32 を再起動します。
  再起動の前に、RTC メモリ（`RTC_NOINIT_ATTR`）に「再起動後の動作」（すぐ始める / 自動判別する）を残します。
- 自動判別は、各 `setter_*.cpp` の `detect()` で行います（各ツールの読み取り関数をそのまま使います）。
  見つかった通信速度は `presetBaud()` で設定してから `setup()` を呼びます。
  種類を 1 つ調べるたびに UART を止め、ピンの設定（エコーあり回路の TX 制御、Hitec のプルダウン）を元に戻します。
  PWM は `pwm::detectByMotion()` で、終わったら LEDC を TX ピンから外します。
- 選んだ種類は NVS の名前空間 `servosarego`、キー `type` に保存します（0〜7 = メニューの番号 - 1）。
- `servo_bus.h` は統合前の 6 ツールと同じものです。各 `setter_*.cpp` ごとに別々の状態を持ちますが、
  同時に動くのは選んだ 1 種類だけです。
